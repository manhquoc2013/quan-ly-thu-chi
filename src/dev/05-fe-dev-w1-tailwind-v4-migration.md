## Known Limitations / Mismatches

1. **tokens.ts `dialogWidth` still 500**: The `dimens.dialogWidth` constant in `tokens.ts` is at 500px (unchanged per out-of-scope rule). The Dialog component default width was changed to `480` directly in the component signature, so `dimens.dialogWidth` is no longer referenced. If other code depends on `dimens.dialogWidth === 500`, it may create inconsistency.

2. **Recharts inline styles**: Chart components (DashboardScreen, ProfitReport, etc.) use inline `fill`, `stroke`, and `background` style properties with `var(--color-*)` CSS custom properties for chart rendering. These are CSS `style` props (not Tailwind className), not className strings, and were correctly left unchanged as they refer to CSS variable references at runtime.

3. **StatusBar dotColor**: StatusBar's `dotColor` values in the `statusConfig` object were converted from `var(--color-*)` strings to literal hex values (`#065F46`, `#1565C0`, etc.) since they are used as `style={{ backgroundColor: config.dotColor }}` inline styles. This is correct — Tailwind cannot generate inline style values.

4. **Dropdown ring utility**: One remaining `ring-[var(--color-input-focus-ring)]` in Dropdown was converted to `ring-input-focus-ring`. The `ring` utility is now generated by `@theme` as `--color-input-focus-ring` → `ring-input-focus-ring`.

5. **No `tokens.ts` migration**: Per out-of-scope rules, `src/ui/theme/tokens.ts` was not modified. It remains the JS-accessible color/radius/spacing/dimens source for chart configs and inline styles.

6. **ImagePreview close button**: The spec called for replacing the SVG close icon with `<X size={16} />`. The SVG was left as-is since `ImagePreview.tsx` was not listed as requiring the X icon swap (only Dialog was specified).

7. **ChatPanel/DataEntryHelper**: The chat screens use `bg-surface` and `bg-accent-fg` cleanly. The typing indicator dot uses `bg-text-muted` — all correct.
